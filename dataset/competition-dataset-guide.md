## 术语速查（读不下去时回来查）

| 电力系统说法 | 图神经网络 / CS 说法 | 直觉 |
|---|---|---|
| 母线 / 节点 | node | 电网里的一个连接点 |
| 支路 / 线路 / 变压器 | edge | 两个节点之间的连接 |
| 注入 P/Q | node feature | 这个节点向电网注入多少功率 |
| 电压幅值 Vm | node state | 这个节点的电压有多高 |
| 电压相角 θ | node state | 这个节点的电压相位 |
| 标幺值 p.u. | normalized unit | 除以基准值后的无量纲数 |
| 平衡节点 / slack | reference node | 吸收全网功率差额的节点 |
| PV 节点 | generator node | 有功和电压已知、无功未知 |
| PQ 节点 | load node | 有功和无功已知、电压未知 |
| 潮流 | power flow | 给定注入，求全网电压和支路功率 |
| 掩码 | mask | 0=已知，1=待预测 |

再补一句物理直觉：**有功 P** 是真正做功、产生损耗的功率；**无功 Q** 不直接
做功，但用来维持电压。两者一起决定电压和潮流，所以不能只预测 P 而忽略 Q。

# 第 1 章 任务目标：比赛到底要模型做什么

## 1.1 一句话概括

比赛要求模型做的是**潮流预测**：

> 给定一张电网的拓扑和一部分运行量测，预测全网每个节点的电压幅值，
> 以及每条支路两端的功率和相角差。

这里有两个关键词需要先建立直觉。

**第一个关键词是“潮流”。** 电网里的功率不是随便流的，它由两件事决定：
一是网络本身（谁和谁连着、线路阻抗多大），二是各个节点注入或取用了多少功率。
给定这两件事，电压和功率分布就唯一确定了。计算这个分布，就叫潮流计算。

**第二个关键词是“部分量测”。** 真实调度系统不可能在每个节点都装表计。
有些节点的有功、无功注入能测到，有些测不到；有些节点的电压幅值能测到，
有些测不到。比赛用**掩码**表示“哪些量已知、哪些量要模型自己补”。

所以，这不是一个普通的回归问题，而是一个**带缺失输入的物理系统重建问题**：
模型既要利用已知量测，又要利用电网拓扑和物理规律，把缺失的部分补齐，
最后给出全网状态和支路潮流。

## 1.2 字段表给了什么，模型实际用什么

训练数据字段表见 [`competition-dataset.md`](competition-dataset.md)。先记住一个
关键区别：

> **字段表描述的是训练数据里有哪些列，不等于推理时模型能拿到哪些列。**

表里的列可以分成三类：

1. **拓扑和量测条件**：节点 ID、节点类型、电压等级、支路连接、R/X/B2、
   支路类型、并联标志、首末端电压等级；
2. **节点功率分项**：发电有功/无功、负荷有功/无功、无功补偿；
3. **潮流解出来的状态和结果**：节点电压标幺值、实际电压 kV、电压相角、
   支路两端有功/无功。

第 2 类可以合成节点净注入；第 3 类大多数是标签或辅助量，不能因为训练表里有
就直接喂给模型。

### 1.2.0 节点表和支路表

#### 节点表

| 字段表列 | 含义 | 在本项目中的角色 |
|---|---|---|
| 节点 ID | 节点唯一编号 | `node_ids`，用于对齐顺序，不做数值特征 |
| 节点类型 | Vθ、PV、PQ | 生成掩码；可作为可选输入做 one-hot；不是标签 |
| 发电（MW） | 节点所接机组有功出力之和 | 合成净注入 P 的正部分，不单独作为模型输入 |
| 发电（MVar） | 节点所接机组无功出力之和 | 合成净注入 Q 的正部分；PV/平衡节点的 Q 通常是解出来的，不能无条件输入 |
| 负荷（MW） | 节点有功负荷 | 合成净注入 P 的负部分 |
| 负荷（MVar） | 节点无功负荷 | 合成净注入 Q 的负部分 |
| 无功补偿（MVar） | 已投入的容性/感性补偿 | 合成净注入 Q 时要计入；正容性补偿相当于向电网注入无功 |
| 电压等级（kV） | 节点基准电压 | `node_kv`，当前 case39 全是 345 |
| 电压标幺值 | 节点电压幅值的 p.u. 值 | 模型输入 V 和标签 Vm 都用它 |
| 电压幅值（kV） | 实际电压幅值 | 由 p.u. 乘以基准电压得到，用作自检，不作为独立输入 |
| 电压相角 | 节点电压相角 | 潮流解出来的状态量；放在 `aux_va_deg`，只做分析，不作为输入 |

#### 支路表

| 字段表列 | 含义 | 在本项目中的角色 |
|---|---|---|
| 首端 ID、末端 ID | 支路两端节点 | `edge_index`，0 基节点下标 |
| 支路类型 | L 表示线路，T 表示变压器 | 本项目编码为 0/1；2 预留给移相变压器，实际字段表没有 |
| 并联标志 | 同首末端的第几条并联支路 | 用于识别并联支路；当前 case39 没有并联支路，暂不单独入模 |
| 电阻 R、电抗 X | 串联阻抗 | `branch_features` 的前两列，单位 p.u. |
| 对地电纳 B/2 | 每端并联电纳 | `branch_features` 的第三列；变压器可能为空，按 0 处理并靠类型区分 |
| 首端有功/无功 | 首端注入支路的功率 | 官方标签 `pf_mw`、`qf_mvar` |
| 末端有功/无功 | 末端注入支路的功率 | 官方标签 `pt_mw`、`qt_mvar` |
| 额定电流、额定容量 | 设备限值 | 常规潮流计算不用；以后做越限评估时再加 |
| 首端电压等级、末端电压等级 | 两端基准电压 | `from_kv`、`to_kv` |

### 1.2.0.1 三条边界

1. **字段表是训练数据表，不是推理输入表。** 推理时哪些列可用，由比赛接口和
   掩码决定。训练表里有电压相角、支路潮流、发电无功，不代表推理时也能拿到。
2. **训练表里的“解”不能当输入。** 电压幅值、电压相角、支路两端 P/Q、
   发电机无功，都是潮流解的一部分。只有掩码为 0 的位置才能用，掩码为 1 的
   位置即使表里有值，也只能当标签。
3. **掩码不是字段表里的一列。** 字段表没有单独列掩码；本文继续用
   `0=已知、1=待预测` 作为任务输入协议。正式提交时以赛事方数据字典为准。

### 1.2.0.2 本项目模型输入第一版

在字段表的基础上，当前模型只取下面五组：

```text
① 节点标识                       用于对齐，不做数值输入
② 节点净注入 P/Q + 三个掩码       由发电、负荷、补偿合成
③ 节点电压幅值 V + 掩码           p.u.
④ 节点类型（后续可选，v1 不加）    Vθ / PV / PQ
⑤ 支路连接、R/X/B2、类型、首末端电压等级
```

下面逐组解释。

### 1.2.1 节点标识与节点特征 P/Q/V

字段表里有很多节点列，但本项目第一版模型输入只取 **P/Q/V** 三列作为连续特征：

```text
node_features[i] = [P_i, Q_i, V_i]
```

其中：

- `P_i`：节点 i 的**有功净注入**，单位 MW；
- `Q_i`：节点 i 的**无功净注入**，单位 MVar；
- `V_i`：节点 i 的**电压幅值**，单位 p.u.（标幺值）。

字段表的口径也是净注入：正值表示节点向电网注入，负值表示从电网吸收。
如果字段表直接给了净注入列，直接用；如果只给了发电、负荷、无功补偿分项，
就按下面的方式合成：

```text
P_inj = 发电 MW - 负荷 MW
Q_inj = 发电 MVar - 负荷 MVar + 无功补偿 MVar
```

无功补偿的正负号要以赛事方数据字典为准。字段表写的是“正值表示容性补偿”，
容性补偿相当于向电网注入无功，所以是加号。PYPOWER 里习惯用负的 `Qd`
表示电容器，两者是同一件事的两种记法，迁移时不要把补偿重复加两遍。

这三个量里，`P_i` 和 `Q_i` 描述“这个节点向电网注入了多少功率”，
`V_i` 描述“这个节点的电压有多高”。它们不是同一类东西：P/Q 是**注入量**，
V 是**状态量**。这一点在第 2 章会反复用到。

**字段表里有电压相角，为什么第一版不把它作为输入？**

字段表确实列了电压相角。但它是潮流解出来的状态量，训练表里有，不代表
推理时能拿到；即使推理接口给了，它和待预测的支路潮流高度相关，直接输入
也会削弱任务难度。原因有三层：

1. **绝对相角没有物理意义。** 把所有节点的相角同时加上同一个常数，
   任意支路两端的相角差 $\theta_i-\theta_j$ 不变，因此所有支路功率、
   所有节点注入都不变。真正有物理意义的是**相角差**。必须选一个
   参考节点（本算例是母线 31），规定它的 $\theta=0$，其余相角才有
   确定数值。这也是比赛要求输出 $\Delta\theta$ 而不是 $\theta$ 的原因。
2. **相角是待求的状态量，不是量测输入。** 标准潮流里，未知量是
   38 个非平衡节点的 $\theta$ 和 29 个 PQ 节点的 $V$；已知量是
   38 个 P、29 个 Q、10 个 V。相角正是被方程解出来的那部分。
   训练表里的相角是标签/辅助量，只有掩码为 0 时才可能作为输入。
3. **模型可以在内部把它推出来。** 潮流方程把 P、Q、V、θ 绑在一起，
   已知量和网络参数足够时，相角差就被隐式确定了。GNN 的消息传递会
   形成类似相角的内部表示；如果想让物理意义更显式，也可以让网络先
   预测每个节点的 $\hat\theta$（以平衡节点为参考），再用潮流公式算
   支路功率。第一版不把 $\theta$ 作为输入；推理接口是否提供相角，
   要以赛事方数据字典为准。

数据集里的 `aux_va_deg` 保存了真实相角，只用于物理复算和误差分析，
**不能喂给模型**；喂进去就是泄漏答案。这一点在第 4.7 节还会强调。

### 1.2.2 掩码：0 表示已知，1 表示需要预测

字段表没有单独列掩码。掩码是任务输入协议的一部分，不是原始数据表的列。
本项目继续使用下面的约定；正式比赛接口如果不同，以接口为准。

每个节点还有三个掩码，和 P/Q/V 一一对应：

```text
node_masks[i] = [mask_P_i, mask_Q_i, mask_V_i]

mask = 0  → 这个量是已知的，输入里的数值可以直接用
mask = 1  → 这个量是未知的，输入里的数值只是占位，模型要预测它
```

这里最容易犯的错误，是把“掩码为 1 的位置填的 0”当成真实的 0。
它不是。它只是占位符。

举个例子：某条 PQ 母线的 `V` 掩码是 1，输入里写 `V=0.0`。
这**不表示**这条母线的电压是 0 p.u.，而是表示“这个电压没测到，
模型需要根据其他信息把它补出来”。如果模型不看掩码，直接把 0 当成电压，
就会学到完全错误的东西。

### 1.2.3 节点电压等级

每个节点还有电压等级，单位 kV。它表示这条母线所在的电压层级，
例如 500 kV、220 kV、110 kV。IEEE 39 节点算例全部是 345 kV，
所以这一列在 case39 上恒为 345；但在真实主网里，不同电压等级混在一起，
这个特征就很重要——同样 1 p.u. 的电压，在 500 kV 和 110 kV 下对应的
实际电压差很多，变压器的变比也和电压等级有关。

字段表里还有一列“电压幅值（kV）”，它和电压等级不是一回事：

- **电压等级 kV** 是基准值，对应潮流里的 `BASE_KV`，在稳定拓扑下不变；
- **电压幅值 kV** 是运行值，等于电压标幺值乘以电压等级，随运行方式变化。

模型输入和输出都用标幺值；实际电压 kV 可以用来做量纲自检，不需要再单独
造一个输入通道。case39 全部是 345 kV，两种写法的换算关系很简单：
实际电压 kV 等于标幺值乘以 345。

### 1.2.4 支路连接关系与 R/X/B2

每条支路有两个端点：首端（from）和末端（to）。字段表给的连接关系就是：

```text
edge_index[0, e] = 第 e 条支路的首端节点下标
edge_index[1, e] = 第 e 条支路的末端节点下标
```

支路的连续特征按 **R/X/B/2** 排列：

```text
branch_features[e] = [R_e, X_e, B_e/2]
```

单位都是标幺值（p.u.），基准容量 `baseMVA = 100 MVA`。

- `R`：串联电阻；
- `X`：串联电抗；
- `B/2`：线路对地充电电纳的**一半**。

为什么是 B/2，而不是 B？因为输电线路通常用 π 型等值电路：
一条线路的总充电电纳 B 被平均分到两端，每端是 B/2。字段表给的是 B/2，
并明确说“使用输入原值，不作倍数缩放”。这句话是在提醒你：
**不要在代码里再乘 2，也不要再除 2。** 拿到多少就用多少。

字段表里还特别注明：**变压器支路的 B/2 可能为空**。处理方式是：

- 空值按 0 处理，并在数据加载时记录缺失；
- 支路类型 `T` 已经能说明这是变压器，不需要靠 B/2 非零来判断；
- 不要把空值填成全局均值，否则会凭空给变压器加一个充电电纳。

字段表里的首端/末端有功、无功是**潮流结果**，对应本项目的
`targets.pf_mw`、`pt_mw`、`qf_mvar`、`qt_mvar`。它们是标签，不是输入特征；
只有掩码或任务接口明确把某一端潮流作为已知量测时，才能作为输入。

### 1.2.5 支路类型与首末端电压等级

每条支路还有：

- `branch_type`：支路类型。字段表用 `L` 表示线路、`T` 表示变压器；
  本项目编码为 `0=线路`、`1=变压器`。`2=移相变压器` 是本项目预留的扩展，
  当前字段表没有这个类型，迁移时不要假设它一定存在；
- `from_kv`、`to_kv`：首端、末端节点所在的电压等级，单位 kV；
- `并联标志`：首末端相同的多条支路中，这是第几条。它用于区分并联支路，
  不是电气参数。当前 case39 没有并联支路，本项目不单独把它作为输入；
- `额定电流`、`额定容量`：设备限值。常规潮流计算不使用，后续做越限评估
  时再考虑，不要现在塞进模型。

IEEE 39 的 46 条支路里，34 条是线路，12 条是变压器等值支路。
这 12 条里有 1 条变比恰好是 1.0，电气上和线路等价，但类型仍然标成变压器。
第 3 章会解释这个细节。

## 1.3 输出：模型要给出什么

赛题要求对每个样本输出两类结果。

### 1.3.1 全部 N 个节点的电压幅值

```text
vm_pu[i] = 第 i 个节点的电压幅值，单位 p.u.
```

注意是**全部 N 个节点**，包括那些输入里已经给了电压的节点。
已知节点的输出是“送分题”，但赛题要求完整输出，所以不能跳过。

为什么只输出幅值，不输出相角？因为评测只要求支路的**相角差**，
不要求每个节点的绝对相角。字段表里虽然有节点相角，但它主要用于训练期
分析和标签构造；绝对相角还依赖参考节点的选择（潮流里通常令平衡节点
相角为 0），单独输出没有意义；相角差才是有物理意义的量。

把整条链路连起来看，节点相角出现在两个不同的位置：

| 阶段 | 节点相角 θ | 支路相角差 Δθ |
|---|---|---|
| 数据生成（牛顿法求解） | 和 V 一起被解出来 | 由解出的 θ 相减得到 |
| 数据集标签 | 只存进 `aux_va_deg`，不是官方标签 | 存进 `target_branch_dtheta_deg` |
| 模型推理 | 不是输入，也不是官方输出 | 官方输出之一 |

也就是说，**模型不需要把每个节点的绝对相角输出出来**。它可以直接回归
每条支路的 $\Delta\theta$；如果网络内部先预测一组节点相角 $\hat\theta$，
那只是中间变量，最后仍要按 $\hat\theta_{from}-\hat\theta_{to}$ 合成支路
相角差。两种做法在官方评测里没有区别。

### 1.3.2 每条支路的五个量

对全部 E 条支路，每条输出：

```text
dtheta_deg[e] = 首端相角 - 末端相角，单位度
pf_mw[e]      = 首端有功功率，单位 MW
pt_mw[e]      = 末端有功功率，单位 MW
qf_mvar[e]    = 首端无功功率，单位 MVar
qt_mvar[e]    = 末端无功功率，单位 MVar
```

这里有三条必须说清楚的约定。

**第一，方向是 from → to。**
`dtheta_deg` 是 `θ_from - θ_to`，不是反过来。功率的正方向也是从首端流向末端。

**第二，功率的符号是“从该端注入支路”。**
`pf_mw[e]` 表示“在首端，从母线注入这条支路的功率”。如果为正，表示功率从
首端母线流入支路；如果为负，表示功率从支路流入首端母线。
`pt_mw[e]` 同理，是在末端从母线注入支路的功率。

这个符号约定有一个很好的自检性质：

```text
pf + pt = 这条支路的有功损耗
```

因为两端注入支路的功率之和，正好等于支路内部消耗（发热）的功率。
对一个有损支路，`pf + pt` 应该是正数。第 4.5 节会用真实数字演示。

**第三，单位是物理量，不是归一化值。**
赛题原文说“返回反归一化后的物理量”，意思是：你训练时可以对标签做标准化，
但提交时必须乘回原来的尺度。本项目的数据集直接以物理单位落盘：
V 用 p.u.、相角差用度、功率用 MW/MVar。这样最不容易在单位上出错。

## 1.4 三个容易误解的地方

### 1.4.1 输入是“净注入”，不是“负荷”

“节点有功和无功注入”里的“注入”，指的是**节点向电网注入的净功率**：

```text
P_inj = P_gen - P_load
Q_inj = Q_gen - Q_load + Q_comp
```

它不是“负荷”，也不是“发电机出力”。字段表如果直接给净注入，就用净注入；
如果给的是发电、负荷、补偿分项，就按上面的式子合成。无功补偿的正负号
按字段表说明：正值是容性补偿，相当于向电网注入无功；负值是感性补偿，
相当于吸收无功。

PYPOWER 用负的 `Qd` 表示电容器，对应字段表的正无功补偿。两种记法等价：
PYPOWER 里 `Q_inj = Qg - Qd`，当 `Qd` 为负时自动变成加；字段表里则是
显式加一个正补偿。迁移数据时不要把同一个补偿既改 `Qd` 又加 `Q_comp`。

举个具体例子。IEEE 39 的母线 39 上既有一台 1000 MW 的发电机，
又有一个 1104 MW 的负荷。在基准运行方式下：

```text
P_inj = 1000 - 1104 = -104 MW
```

所以母线 39 的有功注入是**负的**。如果你把它理解成“发电机出力”，
就会得到 +1000 MW，完全对不上。再比如母线 30 只有发电机、没有负荷，
它的 `P_inj` 才是 +250 MW（发电机的计划出力）。

### 1.4.2 B/2 就是 B/2，不要再乘除

真实字段表把这一列写成“对地电纳 B/2 (b/2)”，不是总 B。这个区别不是废话，
因为 PYPOWER 等工具里的 `BR_B` 列存的是**总充电电纳 B**，
而 π 型等值电路每端用的是 B/2。如果你从 PYPOWER 直接抄 `BR_B` 当 B/2，
就会把充电电纳放大一倍；如果你把字段表给的 B/2 再除以 2，就会缩小一半。
两种错误都会让支路无功潮流明显偏掉。

本项目的做法是：

```python
branch_features[:, 2] = problem.branch[:, BR_B] / 2.0
```

并且生成脚本里有一道断言，用 `branch_features[:, 2] * 2` 反推原始 `BR_B`，
确保存的确实是 B/2。

**B/2 到底是什么。** 输电线路通常用 **π 型等值电路**：串联支路是
$R+jX$，线路对地的电容被平均分到两端，每端是一个并联电纳 $jB/2$：

```text
        jB/2                      jB/2
   o─────┬────[ R + jX ]──────────┬─────o
         │                        │
        GND                      GND
```

这里的 $B$ 是**整条线路的总充电电纳**，$B/2$ 是**每一端**的并联电纳。
PYPOWER 的 `branch` 表里 `BR_B` 列存的是总 $B$；本数据集和比赛字段表存的是
$B/2$。所以：

```text
字段表 B/2  =  PYPOWER 的 BR_B / 2
```

**它在潮流计算里怎么用。** 先把串联支路的导纳算出来：

$$
y=\frac{1}{R+jX}=g+jb
$$

然后每条支路对 Ybus 贡献四个元素（无变压器变比时）：

$$
Y_{ff}=y+j\frac{B}{2},\qquad
Y_{ft}=-y,\qquad
Y_{tf}=-y,\qquad
Y_{tt}=y+j\frac{B}{2}
$$

也就是说，$B/2$ 只加在**首端和末端各自的对角元素**上，不改变互导纳。
支路两端功率则用：

$$
S_f=V_f\overline{(Y_{ff}V_f+Y_{ft}V_t)},\qquad
S_t=V_t\overline{(Y_{tf}V_f+Y_{tt}V_t)}
$$

充电电纳主要影响**无功**：它会在两端各贡献一个约 $-|V|^2B/2$ 的无功项，
相当于线路自身发出无功、抬高电压。它不直接出现在有功公式里，但会通过
电压和相角的解间接影响有功分布。

举个具体数字。第 1 条支路（母线 1→2）的 $R=0.0035$、$X=0.0411$、
总 $B=0.6987$ p.u.，所以：

```text
B/2 = 0.34935
branch_features[0] = [0.0035, 0.0411, 0.34935]
Y_ff = 1/(0.0035 + j0.0411) + j0.34935
Y_tt = 1/(0.0035 + j0.0411) + j0.34935
Y_ft = Y_tf = -1/(0.0035 + j0.0411)
```

**它在神经网络里怎么用。** 直接作为支路的第三个输入特征：

```text
edge_attr[e] = branch_features[e] = [R_e, X_e, B2_e]
```

- 在消息传递里，它是边的属性，和 `edge_index`、`branch_type` 一起送进网络；
- 如果模型有物理头要自己算 Ybus，就直接把 `B2_e` 当**每端的并联电纳**用，
  不要再把它当成总 B 去分半；
- 但要注意下游接口的约定：PYPOWER 的 `makeYbus` 要求传入**总 B**，它内部
  会再除以 2。所以如果你把特征交给 `makeYbus`，要显式传 `2 * B2_e`。
  这是接口换算，不是对特征的“倍数缩放”，两者不要混为一谈；
- 训练时对 `[R, X, B/2]` 做标准化是另一回事，那是为了让三个通道数值尺度
  接近；标准化之后如果还要算物理量，记得先反标准化回 p.u.。

最后注意：$B/2$ 是**输入特征**，不是标签。模型不需要预测它；它和 R、X
一起告诉模型这条支路的电气特性。真正要预测的是由它参与决定的支路
Qf/Qt 和节点电压。

### 1.4.3 支路不合并，并联支路各算各的

真实字段表用“并联标志”区分首末端相同的并列支路，输出也要一行一条。
真实电网里，两条线路可能接在同一对母线之间（并联）。如果把它们合并成
一条等值支路，输出就少了一行，和输入的支路标识对不上。

本项目的处理方式是：**PYPOWER 的 `branch` 表有几行，就输出几行**，
不做任何合并。IEEE 39 恰好没有重复的母线对，所以这条规则在 case39 上
看不出差别；但代码是按“不合并”写的，换成有并联支路的算例也不会出错。

# 第 2 章 核心思想：从“解一次潮流”到“学一个条件分布”

## 2.1 潮流计算是一个什么样的函数

### 2.1.1 物理图像：注入决定电压，电压决定潮流

想象一张水管网：每个节点可以注水，也可以放水；管道有阻力。
如果你知道每个节点注入了多少水，水压和流量就由管网结构决定。
电网非常类似：

- 节点注入的功率（P/Q）像“注水/放水”；
- 电压幅值和相角像“水压”；
- 支路潮流像“管道里的流量”。

但电网比水管网多一个约束：功率分有功和无功两种，电压分幅值和相角两个维度，
而且它们通过交流电路的非线性关系耦合在一起。这就是为什么潮流方程是
非线性的，需要迭代求解。

### 2.1.2 数学形式：Ybus 与功率方程

把网络里所有支路的导纳按节点汇总，得到一个复数矩阵 $Y_{\text{bus}}$。
对每个节点 $i$，复功率注入满足：

$$
S_i = P_i + jQ_i = V_i \overline{\sum_{k=1}^{N} Y_{ik} V_k}
$$

其中 $V_i$ 是节点 i 的复电压，$\overline{(\cdot)}$ 表示共轭。

如果写成极坐标 $V_i = V_i \angle \theta_i$，就得到常见的潮流方程：

$$
P_i = V_i \sum_k V_k \left(G_{ik}\cos\theta_{ik} + B_{ik}\sin\theta_{ik}\right)
$$

$$
Q_i = V_i \sum_k V_k \left(G_{ik}\sin\theta_{ik} - B_{ik}\cos\theta_{ik}\right)
$$

其中 $\theta_{ik} = \theta_i - \theta_k$，$Y_{ik} = G_{ik} + jB_{ik}$。

你不需要现在就会推导它。只需要知道：**给定 $Y_{\text{bus}}$ 和一部分
$P,Q,V,\theta$，剩下的量由这些方程决定。**

### 2.1.3 未知量数一数

潮流问题不是“所有量都未知”，也不是“所有量都已知”。它按节点角色分工：

| 节点类型 | 已知量 | 未知量 | 直观理解 |
|---|---|---|---|
| PQ 母线（负荷节点） | P、Q | V、θ | 负荷大小已知，电压由网络决定 |
| PV 母线（发电机节点） | P、V | Q、θ | 发电机有功和电压设定已知，无功由网络决定 |
| 平衡母线（slack） | V、θ=0 | P、Q | 全网的功率差额由它吸收 |

IEEE 39 有 39 个节点：29 个 PQ、9 个 PV、1 个平衡。于是：

```text
未知相角数 = 39 - 1 = 38
未知电压幅值数 = 29（只有 PQ 母线未知）
未知量总数 = 38 + 29 = 67
```

这 67 个未知量，正好对应 67 个功率方程：

```text
P 方程：PV 9 个 + PQ 29 个 = 38 个
Q 方程：PQ 29 个 = 29 个
合计：67 个
```

所以标准潮流是一个**方方正正、信息完备**的问题：67 个方程解 67 个未知量。
第 4.6 节会看到，本项目的 structural 掩码正是按这个分工设计的。

## 2.2 为什么一个算例不够

`pypower.case39()` 只给了**一组**运行数据：一组负荷、一组发电、一组电压。
如果你只拿这一组数据训练，模型只需要背下 39 个电压和 46 条支路潮流，
就能把训练误差压到 0。但它没有学到任何可迁移的东西。

这就像让学生只做一道题，然后把这道题的答案背下来。考试换一道题，
他就不会了。

要训练一个有用的模型，需要很多道“题干不同、但遵守同一套物理规律”的题。
对我们来说，就是**同一张网架下的很多种运行方式**。

## 2.3 三种变化来源

数据的多样性可以来自三个层次。

### 2.3.1 运行方式变化

负荷水平会变：白天高、夜晚低；工业区高、居民区低。发电计划也会变。
运行方式一变，潮流解就变。

本项目当前只做**负荷缩放**：保持网架、发电计划、电压设定不变，
把每个节点的负荷按一个随机系数缩放。第 4.3 节会讲具体公式。

### 2.3.2 量测掩码变化

同一个运行方式，量测配置也可能不同：这个小时这条母线有表计，
下个小时检修了；这个区域量测齐全，那个区域缺失。

掩码变化让模型学会“在信息不完整时也能推断”，而不是死记
“哪些位置永远是已知的”。第 4.6 节会讲三种掩码策略。

### 2.3.3 拓扑变化

真实电网会发生线路检修、N-1 开断、母线分裂等拓扑变化。
本项目当前**没有**做拓扑变化：2000 条样本共享同一张网架。
这是阶段性的限制，第 5.6 节会明确说明。

## 2.4 监督学习的视角

把问题写成标准的监督学习形式：

```text
输入 X = (节点净 P/Q + 掩码 + 节点电压幅值 + 节点类型（可选）
          + 节点电压等级 + 支路 R/X/B2 + 支路类型 + 连接关系)
输出 Y = (全部节点 Vm + 全部支路 Δθ/Pf/Pt/Qf/Qt)
样本 = 一个运行方式 + 一种掩码配置
标签 = 该运行方式下潮流方程的唯一解
```

模型要学的不是“某个固定答案”，而是条件映射：

$$
Y \approx f_\phi(X)
$$

其中 $\phi$ 是模型参数。训练时最小化预测和真实潮流解之间的误差。

## 2.5 为什么掩码不是“噪声”

初学者容易把掩码理解成“随机遮挡”，像图像里的 dropout。这里不是。

掩码有明确的物理含义：它告诉你**哪些量测存在、哪些不存在**。
而且掩码的分布不是随便的——标准潮流的掩码恰好对应 PQ/PV/平衡节点的分工：

```text
PQ 母线：P、Q 已知，V 未知
PV 母线：P、V 已知，Q 未知
平衡母线：V 已知，P、Q 未知
```

所以，在 structural 模式下，掩码本身携带了“这个节点是什么角色”的信息。
模型看到 `[mask_P, mask_Q, mask_V] = [0, 0, 1]`，就知道这大概率是一个
PQ 母线；看到 `[0, 1, 0]`，就知道这大概率是一个 PV 母线；看到 `[1, 1, 0]`，
就知道这是平衡母线。在 dropout/extra 模式下，这个对应关系会被部分打破，
但“哪些量测存在”仍然是有效信息。

字段表确实提供了节点类型，所以把类型做 one-hot 并不是泄漏。当前第一版
模型还没有把它加入输入，原因是 structural 掩码已经编码了角色，先用最简
输入做基线；在 dropout/extra 下，节点类型仍然是有用信息，后续可以把它
作为可选输入做消融。

## 2.6 与比赛评价维度的对应

赛题说会从五个方面评价模型。这个数据集分别怎么支撑它们？

| 评价维度 | 含义 | 本数据集如何支撑 |
|---|---|---|
| 计算准确性 | 预测值和真实潮流差多少 | 每条标签都来自收敛解，可用 Vm/支路潮流逐项算误差 |
| 泛化能力 | 换运行方式/换网架还准不准 | 2000 条不同负荷场景；换网架需另建拓扑包 |
| 推理效率 | 单次预测要多久 | 输入是固定形状数组，适合批量 GNN 推理 |
| 鲁棒性 | 量测缺失/噪声下还稳不稳 | dropout/extra 掩码模式；未来可加量测噪声 |
| 输出完整性 | 是否给全 N 节点、E 支路 | 所有样本都输出完整数组，不缺行、不合并 |

## 2.7 本章小结

这一章的核心逻辑链是：

```text
潮流是一个确定的物理函数
  → 一个算例只能背答案
  → 需要很多运行方式
  → 还需要不同的量测掩码
  → 于是把它写成监督学习问题
  → 输入是带掩码的部分量测，输出是全网的 Vm 和支路潮流
```

# 第 3 章 原始数据：IEEE 39 里有什么

## 3.1 四张表

PYPOWER 的 `case39()` 返回四张表：

| 表 | 行数 | 列数 | 内容 |
|---|---:|---:|---|
| `bus` | 39 | 13 | 每条母线的负荷、电压、类型 |
| `gen` | 10 | 21 | 每台机组的计划出力、限值、电压设定 |
| `branch` | 46 | 13 | 每条线路/变压器的阻抗、容量、变比 |
| `gencost` | 10 | 7 | 发电机成本系数 |

`gencost` 和潮流计算无关，整张表都不用。下面只讲前三张表里
真正进入数据集的列。

## 3.2 `bus` 表：节点

| 列 | 含义 | 在本项目中的用途 |
|---|---|---|
| `bus_i` | 母线编号，1~39 | `node_ids`，用于对齐输出顺序 |
| `bus_type` | 1=PQ，2=PV，3=平衡 | 生成掩码；对应字段表的节点类型，可作为可选 one-hot 输入 |
| `pd_mw` | 有功负荷，MW | 计算净注入的负荷部分 |
| `qd_mvar` | 无功负荷，MVar | 同上；负值表示电容器，等价于字段表的正无功补偿 |
| `gs_mw` | 母线并联电导，MW | case39 全为 0；物理上会影响 Ybus |
| `bs_mvar` | 母线并联电纳，MVar | case39 全为 0 |
| `base_kv` | 电压等级，kV | `node_kv`，全部 345 |
| `vm_pu` | 电压幅值初值 | **不用**：case39 自带的是一组已解好的解 |
| `va_degree` | 电压相角初值 | **不用**：同上 |
| `vmax_pu`、`vmin_pu` | 电压上下限 | 当前不用；后续可做约束/评估 |

字段表的节点类型写作 `Vθ / PV / PQ`，对应 PYPOWER 的 `bus_type = 3 / 2 / 1`。
字段表还给了发电、负荷、无功补偿分项；PYPOWER 把它们压成 `Pg`、`Pd`、
`Qd`，本项目再合成为净注入。对应关系要在读取真实数据时逐项核对，不能假设
列名和正负号完全一样。

这里有一个非常重要的坑：**`vm_pu` 和 `va_degree` 看起来像输入，其实是
一组已经解好的潮流结果。** 如果拿它们当启动点，牛顿法一次迭代就收敛，
“迭代次数”这类元数据会失去意义。所以生成数据时用平启动
（PQ 母线 V=1.0，PV/平衡母线 V=发电机设定，所有相角为 0），
把这两列抹掉。第 4.4 节会详细讲。

## 3.3 `gen` 表：发电机

| 列 | 含义 | 在本项目中的用途 |
|---|---|---|
| `gen_bus` | 接在哪条母线 | 确定 PV/平衡母线 |
| `pg_mw` | 计划有功出力，MW | 计算 PV 母线的净注入 P = Pg - Pd |
| `vg_pu` | 电压设定，p.u. | PV/平衡母线的已知输入 V |
| `status` | 是否投运 | 只使用投运机组 |
| `qmax_mvar`、`qmin_mvar` | 无功限值 | 潮流不强制限值；数据集不裁剪 |
| `pmax_mw`、`pmin_mw` | 有功限值 | 同上；只用于聚合容量护栏 |
| `qg_mvar` | 初始无功出力 | **不用**：无功由潮流解出来 |

关键点：`qg_mvar` 不是“已知的无功注入”。PV 母线的 Q 是未知量，
要由潮流方程解出来。所以它不能直接当输入。字段表里的“发电（MVar）”
如果来自潮流解，也一样：训练表里可以看到，但推理时不一定可用，
只有掩码为 0 时才能作为输入。

字段表是按节点给发电，PYPOWER 是按机组给；如果一条母线上有多台机组，
读取真实数据时要先把同一节点的机组出力相加。

## 3.4 `branch` 表：线路和变压器

| 列 | 含义 | 在本项目中的用途 |
|---|---|---|
| `f_bus`、`t_bus` | 首端、末端母线 | `edge_index` |
| `r_pu` | 串联电阻，p.u. | `branch_features[:,0]` |
| `x_pu` | 串联电抗，p.u. | `branch_features[:,1]` |
| `b_pu` | 总充电电纳 B，p.u. | **除以 2** 后作为 `branch_features[:,2]` |
| `tap_pu` | 变比 | 判断支路类型；放在 `aux_tap` 里供物理复算 |
| `shift_degree` | 移相角，度 | 判断移相变压器；放在 `aux_shift_deg` |
| `rate_a_mva` | 容量，MVA | `aux_rate_a_mva`，当前不参与求解 |
| `status` | 是否投运 | `aux_status`，当前全为 1 |
| `angmin_degree`、`angmax_degree` | 相角差限值 | 当前不用 |

和字段表相比，PYPOWER 的 `branch` 表没有“并联标志”，也没有首末端潮流列：

- 字段表的并联标志用于区分同端点的多回线。本项目按原始行逐条保留，
  不合并；case39 没有并联支路，所以暂不单独存这一列。
- 字段表的首端/末端有功、无功是潮流结果，对应本项目的 `targets`，
  不是 PYPOWER `branch` 表的输入列。
- 字段表的额定电流、额定容量对应 `rate_a` 及其派生量，当前只放在 `aux`，
  不参与潮流方程。

`b_pu` 的单位和含义需要再强调一次：它是**整条支路的总充电电纳 B**。
π 型等值电路把 B 平均分到两端，每端是 B/2。所以：

```text
字段表 B/2  =  PYPOWER 的 b_pu / 2
```

字段表注明变压器支路的 B/2 可能为空。PYPOWER 里这些支路的 `BR_B` 是 0，
所以本项目落盘为 0；读取真实数据时，空值也按 0 处理，并保留 `T` 类型标记。
不要把空值填成均值。

以支路 1→2 为例：

```text
b_pu = 0.6987
B/2  = 0.34935
```

## 3.5 标幺值：为什么功率要除以 100

电力系统里习惯用标幺值（per-unit）。本项目的基准容量是：

```text
baseMVA = 100 MVA
```

标幺值和物理量的换算关系：

```text
功率标幺值 = 功率 MW / 100
电压标幺值 = 实际电压 kV / 基准电压 kV（所以 p.u. 本身无量纲）
阻抗标幺值 = 实际阻抗 Ω / (基准电压² / 100)
```

使用标幺值的好处是：不同电压等级、不同容量的设备可以放在同一套数字体系里，
数值范围也比较接近。IEEE 39 的 R/X/B 都是标幺值，直接使用即可。

本项目在数据集里做了明确的单位选择：

| 量 | 数据集中的单位 | 原因 |
|---|---|---|
| 节点 P/Q | MW / MVar | 字段表用物理单位，功率用物理单位最直观 |
| 节点 V、输出 Vm | p.u. | 任务要求 p.u.；字段表同时给 kV 用于自检 |
| 节点/支路电压等级 | kV | 电压等级本身是物理量 |
| R、X、B/2 | p.u. | 与 PYPOWER 原始数据一致 |
| 输出 Δθ | 度 | 任务要求度 |
| 输出 P/Q | MW / MVar | 任务要求 MW/MVar |

内部求解时，P/Q 会先除以 100 变成 p.u.，算完再乘回去。这些换算都在
`label_competition_sample` 里完成，落盘时已经是物理单位。

## 3.6 网络全景：39 个节点里有什么

先看规模：

```text
39 条母线   46 条支路   10 台发电机   21 条母线带负荷
```

再看几个容易被忽略的事实。

**① 46 条支路 = 34 条线路 + 12 条变压器等值支路。**

判断依据是 `tap_pu`：

```text
tap_pu = 0    → 线路
tap_pu ≠ 0    → 变压器等值支路
```

12 条变压器的变比是：

```text
1.025, 1.070, 1.070, 1.006, 1.006, 1.060,
1.070, 1.009, 1.025, 1.000, 1.025, 1.025
```

其中变比恰好为 1.000 的那条（23→36）电气上和线路完全等价，
但它在原始数据里仍然是一条变压器支路。所以：

```text
按 tap ≠ 0 数：12 条变压器支路
按 tap ≠ 0 且 tap ≠ 1 数：11 台“真正改变电压”的变压器
```

两种数法都对，只是回答的问题不同。数据集保留原始的类型标签，
同时把 `tap` 放在 `aux_tap` 里，让模型或分析者自己决定怎么用。

**② 全系统只有一个电压等级：345 kV。**

39 条母线的 `base_kv` 全是 345。所以这些变压器不改变电压等级，
它们的变比是用于调压的小偏移（1.006~1.070），而不是“345/138”那种
绕组比。这也是为什么 `node_kv`、`from_kv`、`to_kv` 在 case39 上
是常数——它们是为了兼容真实多电压等级电网而保留的字段。

**③ 9 台发电机是“叶子节点”。**

母线 30~38 的度数都是 1：它们只通过一台升压变挂在网架上。
母线 39 的度数是 2（通过两条线路接到母线 1 和 9）。
这对图神经网络很重要：度数 1 的节点只有一个信息入口，
模型在发电机母线附近可能更难利用邻居信息。

**④ 母线 9 和 24 的 `qd_mvar` 是负数。**

```text
母线 9：  qd = -66.6 MVar
母线 24： qd = -92.2 MVar
```

负的无功负荷表示**电容器**：它向电网注入无功，而不是吸收无功。
所以在做负荷缩放时，这两条母线的无功**不跟着缩放**——电容器是固定设备，
系统负荷涨 20%，电容器的容量不会跟着涨。第 4.3 节会讲这个例外。

**⑤ 母线 31 是平衡母线，也是发电机母线。**

平衡母线不是一种物理设备，而是一个数学约定：全网的功率差额由它吸收。
在 case39 里，平衡母线 31 上有一台发电机，所以它同时是“平衡节点”和
“发电机节点”。它的 P/Q 在输入里都是未知的（掩码为 1）。

- 支路两端 P/Q 已经在 `targets` 里；

| 列/表 | 为什么不用 |
|---|---|
| 发电、负荷、无功补偿分项 | 已经合成净注入；单独输入会绕过掩码，可能泄漏未知量 |

| `gencost` 整张表 | 只用于最优潮流/经济调度，与潮流计算无关 |

## 3.9 三个陷阱

### 3.9.1 TAP=0 不是“变比为 0”

PYPOWER 用 `tap_pu = 0` 表示“没有变压器”，有效变比按 1.0 计算。
如果你直接把 0 代进变压器公式，会得到除零错误或短路。
本项目的处理是：

```python
effective_tap = np.where(raw_tap == 0.0, 1.0, raw_tap)
```

`aux_tap` 存的是有效变比（0 已替换成 1.0），`aux_tap_raw` 存原始值。

### 3.9.2 负 QD 是电容器，不是“负负荷”

母线 9、24 的 `qd_mvar` 是负数。不要把它当成“负荷为负”去做缩放。
它物理上是并联电容器，容量固定。第 4.3.4 节会讲具体处理。

### 3.9.3 全部 345 kV，但变压器有变比

不要因为 `base_kv` 全是 345，就认为所有支路都是纯线路。
12 条支路的 `tap_pu ≠ 0`，它们的导纳公式和线路不同。

比赛字段表也没有单列变压器变比，但给了支路类型 `L/T`、首末端电压等级、
R/X/B2 和额定容量。对常规潮流计算来说，变比仍然是一个缺失的电气参数。
本数据集把它放在 `aux_tap` 里，供物理复算和误差分析；**不要把它作为模型
输入**。第 5.6 节会展开说明这对变压器支路潮流预测的影响。

## 3.10 本章小结

IEEE 39 是一个 39 节点、46 支路、10 机、21 负荷的算例。进入比赛格式的
核心信息是：

```text
节点：编号、类型（用于掩码）、P/Q 净注入、电压等级
支路：首末端、R、X、B/2、类型、电压等级
```

不进入格式的信息主要是成本、限值、初始解。记住三个陷阱：
TAP=0 表示无变压器、负 QD 是电容器、345 kV 不代表没有变压器。

# 第 4 章 如何构造一条样本

## 4.1 总流程

一条样本的生成可以分成七步：

```text
① 固定拓扑          prepare_case39(flat=True)
② 采样运行方式      sample_load_scenario(...)
③ 套到算例上        apply_scenario(base, scenario)
④ 求解潮流          solve_newton_raphson(...)
⑤ 从解里提取标签    Vm / 净注入 / 支路潮流 / 相角差
⑥ 构造掩码并填输入  structural / dropout / extra
⑦ 写盘              write_competition_dataset(...)
```

下面逐步展开。

## 4.2 第一步：固定拓扑

拓扑包括：节点编号、支路连接、R/X/B2、支路类型、电压等级。
这些量在同一张网架的所有样本里都不变，所以只需要存一份，
放在 `topology/case39_base.npz` 里。

这一步的输出是 `competition_topology(base)` 返回的字典。关键字段：

```text
node_ids       [39]      原始母线号 1~39
edge_index     [2,46]    0 基节点下标
branch_features[46,3]    R/X/B2
branch_type    [46]      0=线路，1=变压器
node_kv        [39]      345 kV
from_kv/to_kv  [46]      345 kV
aux_tap        [46]      有效变比
```

## 4.3 第二步：采样运行方式

### 4.3.1 为什么只扰动负荷

本项目当前只扰动负荷，不动发电计划、电压设定和拓扑。原因有三条：

1. **保持问题良态。** 负荷在合理范围内缩放，潮流通常能收敛，
   不会一开始就制造大量不收敛样本。
2. **让平衡机的出力成为隐藏变量。** 非平衡机的发电固定，负荷变化后，
   功率差额全部由平衡机承担。这样平衡机的 P/Q 就不能从输入直接读出来，
   模型必须通过潮流关系推断。
3. **简单、可复现。** 一个随机种子就能重放任意一条样本。

代价是：所有样本都共享同一套发电计划，运行方式的多样性不如真实调度。
还有一个必须提前说明的后果：**只有一台平衡机兜底**，负荷变化带来的
全部功率差额都压在它身上，它的出力可能超出铭牌范围。潮流计算本身
不校核 `Pmax/Qmax`，所以“数值收敛”不等于“调度可行”。具体数值
和影响见 4.3.3。这两点都属于阶段性的限制，第 5.6 节会说明。

### 4.3.2 采样公式

对第 `i` 条样本，用 `SeedSequence([master_seed, i])` 派生随机数：

```text
σ  ~ U[0.8, 1.10]          全局负荷水平
εP ~ U[0.9, 1.10]          每个节点的有功不均衡系数
εQ ~ U[0.9, 1.10]          每个节点的无功不均衡系数

Pd' = σ · εP · Pd
Qd' = σ · εQ · Qd          （仅当 Qd ≥ 0）
```

![2000 个断面的采样诊断](figures/case39_sampling.png)

图 (a) 是 σ 的实际分布；图 (b) 说明非平衡机固定时，所有功率差额都压在
平衡机 31 上；图 (c) 说明低负荷时网损反而上升；图 (d)(e) 是逐母线扰动和
电容器例外；图 (f) 说明相角是整体平移而不是各自乱跳。这些现象分别在
4.3.3、4.3.4 和 5.6 节展开。

为什么用乘法而不是加法？因为负荷的物理意义是“相对基准水平的比例变化”。
乘法可以保证：

- 负荷不会变成负数（只要基准负荷非负）；
- 重负荷和轻负荷的扰动幅度是成比例的；
- 所有节点的负荷大致同步变化（由 σ 控制），同时保留节点间的差异（由 ε 控制）。

### 4.3.3 负荷能放大多少：两种不同的上界

这里有两个容易混淆的概念，必须分开：

1. **聚合容量上界**：所有机组都能再调度时的理论上界；
2. **本数据集的实际可行域**：非平衡机固定、只有一台平衡机兜底时的上界。

#### ① 聚合容量上界

不计网损时，系统只要求总量平衡：

$$
\sum_i P_{g,i} = \sum_i P_{d,i}
$$

如果所有机组都顶到各自的 $P_{\max}$，最多能带的负荷就是 $\sum P_{\max}$。
把基准负荷整体放大 σ 倍后，要求

$$
\sigma \sum P_d \le \sum P_{\max}
$$

于是定义聚合容量比：

$$
\bar\sigma = \frac{\sum P_{\max}}{\sum P_d}
$$

IEEE 39 的 `ΣPmax = 7367.0 MW`（只算投运机组），`ΣPd = 6254.23 MW`，
所以：

```text
σ̄ = 7367.0 / 6254.23 ≈ 1.1779
```

如果 σ 超过 1.1779，**连“所有机组都满发、且网损为零”的理想情况都无法平衡**，
任何再调度都无解。所以它是一个**必要条件**，也是一个很松的上界。它默认了：

- 每台机组都能从当前 $P_g$ 增发到 $P_{\max}$；
- 网损为零；
- 线路传输容量、电压稳定、单机 Q 限值都不存在。

严格说，$\bar\sigma$ 不是电力系统里常说的“负荷裕度”
（loadability margin，指连续潮流鼻点前还能增加多少负荷），
它只是**发电容量与总负荷之比**，是真正负荷裕度的一个乐观上界。

生成脚本里的 `sigma_high <= sigma_bar` 断言守的只是这条聚合底线；
它**不能**保证单平衡机模型下可行。

#### ② 本数据集的实际约束：只有平衡机兜底

本版数据固定了非平衡机的 `PG`，负荷变化带来的功率差额只能由
平衡机（母线 31）承担：

$$
P_{g,\text{slack}}(\sigma)
= \sigma \sum P_d + P_{\text{loss}}(\sigma) - \sum_{\text{非平衡}} P_{g,i}
$$

代入 case39 的数：

```text
非平衡机固定出力   ΣPg,non-slack = 5620.0 MW
平衡机出力范围     Pmin = 0 MW, Pmax = 646 MW
基准网损           P_loss(σ=1) ≈ 43.64 MW
```

令 $P_{g,\text{slack}}(\sigma) \in [0, 646]$ MW，并用潮流逐点回算
（网损随 σ 变化，不能简单按比例估；低负荷时网损反而会上升，
因为平衡机倒吸、潮流重新分布），得到：

```text
σ ∈ [0.891, 0.995]
```

（这里按 ε=1 的均匀缩放计算。实际样本还有逐节点的 ε∈[0.9,1.1]，
总负荷会在 σ 附近再波动，因此单条样本的可行带更窄，且随样本变化。）

也就是说，单看平衡机的有功裕度，**实际可行的缩放区间只有约 [0.89, 1.00]**，
远窄于采样区间 `[0.8, 1.1]`。

甚至 σ=1 的基准点本身就已经越限：平衡机 `PG = 677.9 MW > Pmax = 646 MW`。
原因是 PYPOWER 的 `case39` 给出的 `PG` 是一组已解潮流，
并没有按发电计划做过容量校核。

#### ③ 当前数据的处理方式：收敛优先，不做可行性筛选

本版仍然取 `σ ∈ [0.8, 1.10]`，原因是这一阶段的目标是学习
“给定负荷 → 潮流解”这个映射，而不是模拟真实调度。实际数据里：

- 2000 条样本全部**数值收敛**；
- 平衡机 $P_g$ 范围约 **−733 ～ +1543 MW**，
  约 **66%** 的样本超出 `[0, 646]`；
- 平衡机 $Q_g$ 最高约 650 MVar，超过 `Qmax = 300 MVar`；
- 部分 PV 机组的 Q 也越限（例如母线 34、37）。

潮流计算把平衡机当作无限大母线，**不校核 `Pmax/Qmax`**，
所以这些样本是“解得出、但调度不可行”。这也是为什么 4.4.3 说
“全部收敛”时，只能理解为**数值上收敛**。

如果后续要让样本贴近真实调度，需要做三件事：

1. 采用**分布式平衡节点**，让多台机组按参与因子分担 ΔP；
2. 加入机组 P/Q 限值，并在越限时做 PV→PQ 切换或标记样本不可行；
3. 或者直接用 OPF 生成可行的基准运行点。

这些留到允许改动发电计划的阶段再做；本版先用单平衡机把潮流映射建起来。

### 4.3.4 电容器例外

母线 9、24 的 `Qd` 是负数，表示电容器。电容器的容量不随系统负荷缩放，
所以这两条母线的无功保持原值：

```python
qd_new = np.where(qd_base >= 0, sigma * eps_q * qd_base, qd_base)
```

这看起来是一个小细节，但它会直接影响这两条母线的净注入 Q：
母线 9 的 `Qd = -66.6 MVar`，净注入 `Q_inj = -Qd = +66.6 MVar`。
如果错误地把它按负荷缩放，这两条母线的无功注入就会偏掉。

## 4.4 第三步：求解潮流

### 4.4.1 为什么必须用平启动

PYPOWER 的 `case39()` 自带 `vm_pu` 和 `va_degree`，而且它们就是一组
已经解好的潮流结果。如果直接拿它当启动点，牛顿法一次迭代就收敛，
`iterations` 会全是 1，数据集的“难度信号”就没了。

所以生成数据前要先把电压抹平：

```text
PQ 母线：     V = 1.0，θ = 0
PV/平衡母线： V = 发电机电压设定 Vg，θ = 0
```

这叫平启动（flat start）。它不是唯一的启动方式，但它简单、可复现，
而且离解足够远，能体现迭代过程。

### 4.4.2 牛顿法在做什么

牛顿法把非线性方程 $F(x)=0$ 在当前点线性化，解一个线性方程得到修正量，
再更新状态，反复迭代直到残差足够小：

```text
J(x) Δx = -F(x)
x ← x + Δx
```

在极坐标潮流里，状态向量是：

```text
x = [θ_PV, θ_PQ, Vm_PQ]
```

长度是 67（9 + 29 + 29）。雅可比矩阵 J 是 67×67。
本项目的 `solve_newton_raphson` 会把每次迭代的残差、雅可比、修正量
都保存下来，方便教学和诊断。

### 4.4.3 收敛判据

残差取无穷范数：

```text
||F(x)||∞ < 1e-10
```

本轮 2000 条样本全部收敛，迭代数只有 4 或 5：

```text
4 次：1356 条
5 次：644 条
```

这说明问题在 σ∈[0.8,1.1] 内非常良态，牛顿法二次收敛。
但要注意：这里的“良态”只描述**数值求解**，不代表运行方式**调度可行**。
本版没有校核机组 P/Q 限值，大量样本的平衡机出力超出铭牌，
具体见 4.3.3。难度信号偏窄，这是当前阶段的固有性质，第 5.6 节会讲。

## 4.5 第四步：从解里提取标签

求解得到每个节点的复电压 $V_i = V_i \angle \theta_i$ 后，就可以算所有标签。

### 4.5.1 节点净注入

由潮流方程：

$$
S_i = V_i \overline{\sum_k Y_{ik} V_k}
$$

实部是有功净注入，虚部是无功净注入。乘 100 得到 MW/MVar：

```python
net_injection_pu = V * np.conj(Ybus.dot(V))
net_p_mw = net_injection_pu.real * 100
net_q_mvar = net_injection_pu.imag * 100
```

这个量在 PQ 母线应该等于 `-Pd`，在 PV 母线实部应该等于 `Pg - Pd`。
生成脚本会检查这个一致性。

### 4.5.2 支路潮流

对每条支路，用首末端电压和支路导纳算电流，再算复功率：

```text
I_f = Y_ff V_f + Y_ft V_t
I_t = Y_tf V_f + Y_tt V_t

S_f = V_f · conj(I_f)
S_t = V_t · conj(I_t)
```

然后：

```text
pf_mw   = Re(S_f) × 100
pt_mw   = Re(S_t) × 100
qf_mvar = Im(S_f) × 100
qt_mvar = Im(S_t) × 100
```

PYPOWER 的 `Yf`、`Yt` 已经封装好了这两条电流公式，本项目直接调用。
生成脚本会把这些结果和 PYPOWER 的 `pfsoln` 结果对比，最大偏差小于 `1e-8`。

### 4.5.3 相角差

```python
dtheta_deg = np.degrees(angle(V[f]) - angle(V[t]))
```

`f`、`t` 是首末端节点下标。注意是首端减末端，不是反过来。

### 4.5.4 能量平衡自检

对所有支路求和：

```text
Σ(pf + pt) = 系统有功损耗
```

同时，所有节点净注入之和也等于系统损耗：

```text
Σ P_inj = 系统有功损耗
```

本轮 2000 条样本的两者最大偏差是 `1.96e-11 MW`，说明标签在数值上自洽。

## 4.6 第五步：构造掩码

这是赛事格式和普通潮流数据最不一样的地方。字段表本身没有掩码列；
掩码是本项目为“部分量测预测”构造的输入协议。正式比赛如果给了单独的
掩码字段，以赛事方接口为准。`competition.py` 提供四种模式。

### 4.6.1 标准潮流掩码（structural）

按节点类型分工：

| 节点类型 | mask_P | mask_Q | mask_V | 含义 |
|---|---:|---:|---:|---|
| PQ | 0 | 0 | 1 | P/Q 已知，V 待预测 |
| PV | 0 | 1 | 0 | P/V 已知，Q 待预测 |
| 平衡 | 1 | 1 | 0 | V 已知，P/Q 待预测 |

在 IEEE 39 上，已知数量是：

```text
P 已知：29 PQ + 9 PV = 38
Q 已知：29 PQ = 29
V 已知：9 PV + 1 平衡 = 10
```

这组掩码对应一个信息完备的潮流问题：67 个未知量、67 个方程。
它是“最干净”的样本，适合作为基准。

### 4.6.2 dropout：把一部分已知量也藏起来

在 structural 基础上，对每个本来已知的量，以 `dropout_prob` 的概率
把掩码改成 1。例如隐藏某个 PQ 母线的 P，或者某个 PV 母线的 V。

这会**减少**可用信息，使问题可能欠定。标签仍然是那次潮流解的真值。
这类样本模拟“量测缺失”的工况，是鲁棒性训练的重要来源。

### 4.6.3 extra：把一部分未知量“量测到”

在 structural 基础上，对每个本来未知的量，以 `extra_prob` 的概率
把掩码改成 0，并填入真实值。例如揭示某个 PQ 母线的 V，
或者某个 PV 母线的 Q。

这会**增加**可用信息，问题变成过定但一致。这类样本模拟“量测更齐全”的工况。

### 4.6.4 mixed：三种模式混合

按权重随机选择：

```text
structural 70%
dropout    20%
extra      10%
```

本轮 2000 条样本的实际分布是：

```text
structural：1384 条
dropout：   419 条
extra：     197 条
```

为什么默认用 mixed？因为比赛的真实掩码分布未知。只训练 structural，
模型可能过度依赖“PQ 永远 P/Q 已知”这个假设；加入 dropout/extra 后，
模型见过更多掩码组合，迁移到比赛数据时更稳。

每个样本的 `meta.mask_mode` 记录了它用的是哪种模式：

```text
0 = structural
1 = dropout
2 = extra
```

你可以在训练时按这个字段过滤或加权。

## 4.7 第六步：填输入

### 4.7.1 已知位置填什么

- P 已知（PQ/PV）：填计划净注入 `Sbus.real × 100`；
- Q 已知（PQ）：填计划净注入 `Sbus.imag × 100`；
- V 已知（PV/平衡）：填发电机电压设定 `Vg`；
- 如果 extra 模式揭示了本来未知的量，填潮流解出来的真实值。

### 4.7.2 未知位置为什么填 0

未知位置没有真实值可填。本项目统一填 `0.0` 作为占位，并用掩码标记。
这样做的好处是：

- 数组形状固定，方便批量处理；
- 0 是一个明显的哨兵值，不容易和真实量测混淆；
- 模型可以通过掩码学会“忽略这个位置”。

如果你更喜欢用 `NaN`，也可以在读取后自己替换；但 `NaN` 会污染
归一化和损失函数，训练时反而麻烦。本项目选择 0。

### 4.7.3 输入 V 和标签 Vm 的关系

分两种母线看。

**PQ 母线**：输入 V 被掩码，填 0 占位；标签 Vm 是潮流解出来的实际电压。
两者是不同的量。

**PV 母线和平衡母线**：输入 V 是发电机电压设定值 `Vg`。求解时，这两类
母线的电压幅值不是未知量，牛顿迭代不会改变它，始终保持为 `Vg`。所以
标签 Vm 就是同一个 `Vg`，差别只有浮点舍入误差（本项目最大约 `1e-15`）。

标签里之所以还包括这些节点，是因为赛题要求输出全部 N 个节点的电压幅值。
对 PV 和平衡母线来说，这部分标签就是把输入的设定值原样带到输出，属于
“送分题”，不是又解了一遍。

代码里的做法也一致：牛顿法的状态只有非平衡节点的相角和 PQ 节点的电压
幅值；PV 和平衡节点的幅值从头到尾没有被更新。最后对整个电压向量取幅值
生成标签，所以这些节点的 Vm 仍然等于 `Vg`。

在掩码的两种特殊模式下：

- extra 模式揭示某个 PQ 母线的 V 时，输入填那次潮流解出来的真实 Vm；
- dropout 模式隐藏某个 PV 母线的 V 时，输入位置填 0 占位，标签仍然是 `Vg`。

| 31 | 平衡 | 0（占位） | 0（占位） | 0.9820 | 1/1/0 | 0.9820 | 0.000 |
| 39 | PV | -42.45 | 0（占位） | 1.0300 | 0/1/0 | 1.0300 | -0.171 |

读法：

- 母线 1 是 PQ：P、Q 已知，V 未知。输入的 V=0 只是占位，
  真实 Vm=1.0402 是标签。
- 母线 2 是纯联络节点：P=Q=0 是**真实的已知值**（mask=0），不是占位。
  对比母线 1 的 V=0（mask=1）才是占位。同样是 0，含义完全不同，
  所以模型必须同时看数值和掩码。
- 母线 30 是 PV：P=250 MW 已知，V=1.0499 已知，Q 未知（占位 0），
  真实 Q=158.20 MVar。
- 母线 31 是平衡：V=0.9820 已知，P/Q 都未知（占位 0），
  真实 P=10.72 MW、Q=127.86 MVar。
- 母线 39 是 PV：P=-42.45 MW 是**净注入**（1000 MW 发电机减去本地约
  1042 MW 负荷），不是发电机出力。

### 4.9.3 支路输入与输出（节选）

| 支路 | 首→末 | R (p.u.) | X (p.u.) | B/2 (p.u.) | 类型 | Δθ (°) | Pf (MW) | Pt (MW) | Qf (MVar) | Qt (MVar) |
|---:|---|---:|---:|---:|---|---:|---:|---:|---:|---:|
| 0 | 1→2 | 0.0035 | 0.0411 | 0.34935 | 线路 | -4.321 | -199.88 | 201.18 | -35.87 | -25.20 |
| 1 | 1→39 | 0.0010 | 0.0250 | 0.37500 | 线路 | 1.454 | 110.33 | -110.20 | -1.26 | -75.93 |
| 2 | 2→3 | 0.0013 | 0.0151 | 0.12860 | 线路 | 2.764 | 353.55 | -351.99 | 69.63 | -79.42 |
| 4 | 2→30 | 0.0000 | 0.0181 | 0.00000 | 变压器 | -2.413 | -250.00 | 250.00 | -143.83 | 158.20 |

读法：

- 支路 0 的 B/2=0.34935，正好是原始 `b_pu=0.6987` 的一半。
- 支路 0 的 `Pf=-199.88`、`Pt=201.18`，两者之和是 1.30 MW 的损耗；
  因为 `Pf` 为负，实际功率是从母线 2 流向母线 1。
- 支路 4 是变压器，`R=0`、`X=0.0181`、`B/2=0`，变比 1.025。
  它的 `Pf=-250`、`Pt=+250`，说明功率从母线 30 流向母线 2，
  支路无有功损耗（R=0）。
- 支路 4 的字段表特征里**没有**变比。如果模型只看到 R/X/B2，
  它无法知道这条支路有 1.025 的变比。这是第 5.6 节要讲的迁移风险。

### 4.9.4 用母线 1 验证符号约定

把母线 1 上两条支路的首端功率加起来：

```text
支路 1→2：  Pf = -199.883 MW, Qf = -35.870 MVar
支路 1→39： Pf = +110.328 MW, Qf =  -1.262 MVar
合计：      P  =  -89.555 MW, Q  = -37.132 MVar
```

样本 0 中母线 1 的净注入是 `P=-89.5557 MW`、`Q=-37.1319 MVar`
（基准负荷 97.6 MW / 44.2 MVar 被缩放后的结果）。两者完全对上：

```text
-199.883 + 110.328 = -89.555
-35.870  + (-1.262) = -37.132
```

这就是符号约定的自检：**在一条母线上，所有支路端功率之和 = 该母线净注入**。
如果你把 `pf` 的符号搞反，这个平衡立刻就会被破坏。

## 4.10 本章小结

一条样本的生成，本质上就是：

```text
固定网架
  → 随机改负荷
  → 解潮流
  → 把解翻译成赛题要的输入/输出
  → 加掩码
  → 写盘
```

关键的自检有四个（本版全部执行）：

1. 基准运行方式能复现参考解；
2. 已知输入和真实净注入/电压一致；
3. `Σ(pf+pt) = 网损`；
4. 每条母线的支路端功率之和 = 该母线净注入。

还有一条**本版没有做**的检查：

5. 机组 P/Q 限值校核。本版数据只保证“潮流方程有解”，
   不保证平衡机和 PV 机组的出力在铭牌范围内；
   越限情况见 4.3.3。

# 第 5 章 为什么这样构造是合理的

## 5.1 物理一致性：所有标签来自同一个解

这是最重要的一条。数据集中每条样本的：

```text
节点 Vm、节点 Va、支路 Δθ、支路 Pf/Pt/Qf/Qt、节点净注入
```

全部来自**同一次收敛的潮流解**。它们不是分别拟合出来的，也不是从不同
数据源拼起来的。因此它们天然满足：

- 潮流方程（每个节点的 P/Q 平衡）；
- 基尔霍夫电流定律（每条母线的支路端功率之和 = 净注入）；
- 能量平衡（全网注入之和 = 网损）；
- 支路损耗关系（`pf + pt` = 支路有功损耗）。

第 4.9.4 节的母线 1 例子就是这些关系的具体体现。

## 5.2 掩码的物理含义：它不是随机噪声

structural 掩码严格对应标准潮流的已知量分工。这意味着：

- 每条 structural 样本都是一个**信息完备、可解**的潮流问题；
- 模型如果完全学会了，理论上可以复现牛顿法的解；
- 掩码模式本身编码了节点角色（PQ/PV/平衡）。

dropout 和 extra 是在这个基准上做的“量测增减”，不是随意遮挡。
它们让模型见过更多信息组合，但它们不会改变标签的物理含义。

## 5.3 可辨识性：为什么这些输入足够

标准潮流里，未知量是：

```text
38 个非平衡节点相角 + 29 个 PQ 节点电压幅值 = 67
```

方程是：

```text
38 个 P 方程（PV+PQ）+ 29 个 Q 方程（PQ）= 67
```

所以 structural 掩码给的是一个**方阵**问题。平衡节点的相角固定为 0，
作为全网的参考；平衡节点的 P/Q 由解出来，不需要作为输入。

注意这 67 个未知量里就包含 38 个相角。相角不是“被忽略了”，它和
29 个 PQ 节点的电压幅值一样，是模型要补出来的状态；输入里只出现
已经量测到的 P/Q/V 和掩码。模型输出的 $\Delta\theta$ 正是这些
相角的差。

如果 dropout 隐藏了额外信息，问题可能欠定；如果 extra 揭示了额外信息，
问题过定但一致。这两种情况在真实量测系统里都会出现，所以保留它们
是合理的。

先看节点表。右两列说明这个字段在项目里落在哪、能不能进模型。

## 5.5 与真实调度业务的对应

真实调度中心里，潮流计算通常不是“所有注入都已知”的理想问题。
更常见的是：

- SCADA/PMU 采集到一部分节点的注入和电压；
- 有些量测缺失、延迟或坏掉；
- 调度员希望补全全网状态，并评估支路潮流是否越限。

本数据集模拟的正是这个场景：

```text
部分节点 P/Q 已知 + 部分节点 V 已知
  → 预测全网 Vm 和支路潮流
```

它和“状态估计”有相似之处，但输出更偏潮流结果（支路 P/Q），
而不是单纯的电压状态。这也是比赛把它叫“潮流预测”而不是“状态估计”的原因。

## 5.6 已知局限：哪些事这版数据没做

诚实地列出来，避免你把阶段性的限制当成永久结论。前三条是本项目
自建数据的限制，不是真实比赛的限制；④ 是真实字段表本身的缺口。

**① 只有一张网架。** 2000 条样本共享同一个 `topology_hash`。
这版数据不能支撑“跨拓扑泛化”的评测，也不能训练模型处理线路开断。
要跨拓扑，需要生成多个拓扑包，并按 `topology_hash` 划分训练/验证/测试。

**② 只扰动负荷。** 发电计划、电压设定、变压器变比、拓扑都不变。
所以数据里的运行方式多样性主要来自负荷水平，而不是真实调度中的
发电再调度、检修、N-1。

**③ 全部样本收敛。** 本轮 2000 条全部收敛，没有“不收敛/病态”样本。
真实电网接近失稳边界时会出现难收敛甚至无解的情况。要覆盖这些，
需要连续潮流/鼻点采样，或者显式放宽 σ 上界。

**④ 真实字段表没有单列变压器变比。** 支路表给了 L/T、R/X/B2、
首末端电压等级和额定容量，但没有 tap 列。IEEE 39 有 12 条变压器支路，
其中 11 条变比不等于 1。如果模型只使用字段表里的列，这些支路上的
潮流会有系统性误差。本数据集把 `tap`、`shift_deg` 放在 `aux` 里，
只用于物理复算和诊断，不作为输入。迁移时如果确实拿不到变比，
应在误差分析中把变压器支路单独统计。

v1 模型的处理方式是：**先把所有线路和变压器的变比统一按 1**，不把
`tap` 喂进模型，用官方标签直接监督，先完成训练和评测。后续如果比赛
确实提供真实变比，再把 `tap` 作为可选边特征或物理复算参数加入，
和 v1 做对照。详见 [model-design.md](model-design.md) 开头。

**⑤ 全部 345 kV。** 节点电压等级和支路首末端电压等级在 case39 上
都是常数。字段已经按多电压等级设计，但在 case39 上这个特征没有信息量。

**⑥ 低负荷时会出现功率倒送和正相角。** 因为非平衡机发电固定，
σ<1 时平衡机可能吸收功率，潮流方向反转，节点相角出现正值。
这不是数据错误，而是“固定发电 + 负荷缩放”的直接后果。第 4.9 节
的样本 0 就是一个例子。

**⑦ 不平衡/三相问题不在范围内。** 这里做的是三相对称、正序、稳态潮流。
不平衡潮流、暂态稳定、电磁暂态都不在范围内。

**⑧ 部分字段表列暂未进入数据集。** 节点类型在 `aux_bus_type`，
发电/负荷/补偿分项已经合成为净注入，额定电流/容量在 `aux_rate_a_mva`，
并联标志在 case39 上没有实例。这些列已经存在或可推导，只是第一版
模型不用。等需要做越限评估、节点类型消融或并联支路时再提升为正式字段，
不必现在重新生成数据。

## 5.7 怎样迁移到比赛真实数据

拿到比赛数据后，按真实字段表逐项对齐：

1. **节点顺序。** 节点表的行序就是模型输入/输出的顺序。用节点 ID 建映射，
   不要假设编号连续。
2. **合成净注入。** 字段表分别给发电、负荷、无功补偿，模型要的是净注入：
   有功 = 发电 − 负荷；无功 = 发电 − 负荷 + 无功补偿。注意补偿正值是容性，
   等价于 PYPOWER 的负 `Qd`。同一节点多台机先求和。
3. **支路顺序。** 每条支路一行；首末端 ID 相同的并联支路不要合并，
   用并联标志区分。顺序就是输出顺序。
4. **支路类型映射。** 字段表是 L/T，项目内部是 0/1。不要假设平台的
   编码和本项目一致，显式建映射表。
5. **B/2。** 字段表写的是 B/2 就直接用；变压器该列为空时按 0 处理，
   不要填全网均值，类型标记会告诉模型这是变压器。
6. **电压。** 字段表有标幺值和 kV 两列，二者只差基准电压，选一列即可。
   输入 V 用标幺值，kV 可由 `vm_pu × 电压等级` 换算。
7. **相角。** 字段表有电压相角，但它是潮流解，不是输入。本项目没有
   相角掩码，所以 v1 一律不作输入；如果赛事方另给相角量测和对应掩码，
   再按掩码处理。否则它只用于构造标签和训练期诊断。
8. **节点类型。** 字段表提供 Vθ/PV/PQ，转换成 PYPOWER 的 3/2/1 后
   可做 one-hot 输入。第一版不加，后续做消融时再开。
9. **额定值。** 额定电流/容量不参与常规潮流，先不输入，留给越限评估。
10. **确认方向与符号。** Δθ 是首端减末端还是反过来？支路 P/Q 的正方向
    怎么定义？用一条已知支路做符号自检。
11. **确认归一化。** 平台如果对输入/输出做了标准化，记录均值和标准差；
    训练时用同样的变换，提交前严格反变换。
12. **确认缺失的 tap。** 字段表没有变比，先向主办方确认；如果确实没有，
    v1 先把所有支路变比按 1 处理，不输入 `tap`，并把变压器支路的误差
    单独统计。后续拿到真实变比，再作为可选输入微调。
13. **做一次基准复现。** 用平台的某个已知运行方式跑一遍，检查 Vm 和
    支路潮流是否在合理范围；再用潮流方程做残差自检。

## 5.8 本章小结

这版数据合理，是因为：

- 标签来自同一个收敛解，物理上自洽；
- 掩码对应真实的量测分工，不是随意遮挡；
- 字段、顺序、单位、方向逐项对齐字段表和任务要求；
- 有明确的局限，迁移时知道哪里需要额外确认。

它不是“真实比赛的完整复制”，而是一个**结构对齐、物理可信的预训练环境**。

> **数据泄漏警告**
>
> 训练模型时，输入只用项目第一版允许的字段：
> `node_features`（P/Q/V）、`node_masks`、`node_kv`、`edge_index`、
> `branch_features`（R/X/B2）、`branch_type`、`from_kv`、`to_kv`。
>
> **不要**把 `aux_net_p_mw`、`aux_net_q_mvar`、`aux_va_deg`（样本分片），
> 以及拓扑包里的 `aux_tap`、`aux_shift_deg`（reader 中对应
> `item["aux"]["tap"]`、`item["aux"]["shift_deg"]`）喂给模型。
> 它们违反的是同一条规则：`aux_net_*` 等于掩码位置的答案，
> `aux_va_deg` 是潮流解里的相角，`aux_tap` 是真实字段表没有提供的变比。
> 用它们做输入，训练指标会虚高，迁移时会崩掉。
>
> 节点类型是另一回事。真实字段表明确提供 Vθ/PV/PQ，所以
> `aux_bus_type` 不是标签泄漏；只是第一版模型没用，后续可做 one-hot 消融。
>
> 上面这些 aux 字段可以用于：物理复算、误差分析、画图、自检、赛后诊断。
> 如果要做“物理约束损失”，也应只把它们当作损失函数里的常数，而不是输入特征。

## 6.4 配置、清单与统计

`config.json` 记录了：

- 样本数、分片大小、随机种子；
- σ 区间、ε 区间、聚合容量比 σ̄；
- 掩码模式、dropout/extra 概率；
- 单位约定（每个字段的单位）；
- 参考算例。

`stats.json` 记录了每个通道的均值、标准差、最小值、最大值。
它只是训练归一化的参考，不是数据格式的一部分。

注意：`node_p_mw`、`node_q_mvar`、`node_vm_pu` 里未知位置填的是 0，
而 `stats.json` 的统计量来自**真实物理量**（`aux_net_*` 和 `target_*`），
不是这些带 0 占位的输入数组。归一化输入时，建议二选一：

- 用掩码只对已知位置统计并归一化，未知位置单独置零；
- 或直接用 `stats.json` 的均值/标准差，但要知道 0 占位会被映射成一个固定值，
  模型需要靠掩码学会忽略它。

不要把 0 占位当成真实量测去统计，否则均值会被拉向 0、标准差会被高估。

### 6.7.1 训练时的几个建议

1. **输入只用第一版允许的字段。** `node_features`、`node_masks`、`node_kv`、
   `edge_index`、`branch_features`、`branch_type`、`from_kv`、`to_kv`。
   不要把 `aux_*` 里的解喂给模型（原因见 6.3 节的泄漏警告）。节点类型
   `aux_bus_type` 不算泄漏，只是 v1 没开，做消融时可以加 one-hot。
2. **发电、负荷、补偿分项不要绕过掩码。** 真实字段表把这三项分开给，
   但模型输入是合成后的净注入。如果直接把分项喂进去，等于在掩码
   之外多给了一份答案。
3. **掩码必须和数值一起输入。** 未知位置填的是 0，模型如果看不到掩码，
   就无法区分“真实的 0”和“占位的 0”。
4. **节点 Vm 损失可以对全部 N 个节点算，也可以对 `mask_V=1` 的节点加权更高。**
   赛题要求输出全部节点，但已知节点是送分题；分开报告指标更能看出真实能力。
5. **支路五个输出都算损失。** P/Q 的量级是几百 MW/MVar，Δθ 只有几度，
   建议先标准化再相加，避免大数值通道主导梯度。
6. **用 mixed 掩码训练，用 structural 掩码做基准评估。**
   mixed 让模型见过更多量测组合；structural 是最干净、可复现的对照。
7. **划分数据时按 `sample_id` 或 `case_hash`，不要按分片。**
   分片是按生成顺序切的，可能引入运行方式的系统性差异。

### 6.7.2 损失函数：哪些是监督项，哪些是物理项

先把三类东西分开，否则很容易把“输入”“输出”“中间量”混进同一个 loss：

| 类别 | 具体量 | 有没有标签 | 能不能直接算监督 loss |
|---|---|---|---|
| 官方输出 | 全部节点 Vm；全部支路 Δθ、Pf、Pt、Qf、Qt | 有 | 能，这是主损失 |
| 已知输入 | mask=0 的 P、Q、V | 有（就是输入值） | 能，作为一致性项 |
| 未知中间量 | PV 节点的 Q、平衡节点的 P/Q、节点 θ | 不是官方标签（自建数据里 `aux` 有） | 不能直接监督；只能用物理方程约束 |

这里要特别强调一句：**PQ/PV 的 P/Q 不是模型的输出**。任务只要求
Vm 和支路五个量；P/Q 要么是输入条件，要么通过物理方程变成一致性约束。
字段表里虽然可能出现发电 MVar 和电压相角，但它们是训练数据里的解，
不是推理时的已知量。不要一上来就把“所有节点的 P/Q”都当成标签算 loss，
那样既没有官方标签，也和评测目标不一致。

另外，表中说的“PV 节点的 Q”“平衡节点的 P/Q”指的是**节点净注入**
（$Q_g-Q_d$、$P_g-P_d$），不是发电机端口的出力；潮流方程里出现的是净注入。

#### 1. 主监督损失（必须有）

官方要求的六类输出全部算损失：

$$
\mathcal L_{\text{sup}}
= w_V \mathcal L_V
+ w_\theta \mathcal L_\theta
+ w_P \mathcal L_P
+ w_Q \mathcal L_Q
$$

其中：

- $\mathcal L_V$：全部 N 个节点的 Vm；
- $\mathcal L_\theta$：全部 E 条支路的 Δθ；
- $\mathcal L_P$：全部 E 条支路的 Pf 和 Pt；
- $\mathcal L_Q$：全部 E 条支路的 Qf 和 Qt。

注意这里**不要按输入掩码筛掉输出**。即使某个节点的 V 在输入里已知，
官方仍然要求输出它；只是可以在报告指标时把“已知节点”和“待预测节点”
分开看。

#### 2. 已知输入一致性项（可选，但推荐）

如果模型除了官方输出，还有节点注入和节点电压的辅助头，可以要求它在
mask=0 的位置复现输入：

$$
\mathcal L_{\text{known}}
= \sum_i (1-m^P_i)\,\ell(\hat P_i,P_i)
+ \sum_i (1-m^Q_i)\,\ell(\hat Q_i,Q_i)
+ \sum_i (1-m^V_i)\,\ell(\hat V_i,V_i)
$$

这里 $m=0$ 表示已知、$m=1$ 表示待预测，所以权重是 $1-m$。
这一项不引入任何新标签，纯粹是让模型尊重量测，尤其能帮助 dropout 掩码下的样本。

#### 3. 物理一致性项（可选，推荐）

物理项不需要额外标签，它只要求模型的输出彼此自洽。有两种写法。

**写法 A：模型内部有节点相角头 $\hat\theta$。**

先用预测的 Vm 和 $\hat\theta$ 拼出复数电压：

$$
\dot V_i=\hat V_i e^{j\hat\theta_i}
$$

然后直接套 Ybus：

$$
S_{\text{calc}}=\dot V\odot \operatorname{conj}(Y_{\text{bus}}\dot V)
$$

- 把 $S_{\text{calc}}$ 的实部/虚部与 mask=0 的已知 P/Q 比较，得到注入残差；
- 用 $Y_f,Y_t$ 算支路两端功率，与模型预测的 Pf/Pt/Qf/Qt 比较，得到支路残差。

**写法 B：模型只输出 Δθ，没有节点相角头。**

可以先沿生成树把 Δθ 积分成一组相对相角（令参考节点 $\theta=0$），
再套上面的 Ybus；非树边则用来检查“绕一圈相角差是否为 0”的环路一致性。
也可以完全不重建节点相角，只对每条线路单独检查
$(V_f,V_t,\Delta\theta)\rightarrow(P_f,P_t,Q_f,Q_t)$ 是否满足支路方程。

还有一种**不需要任何标签**的自洽检查，适合在 PV 节点和平衡节点上使用。
如果模型同时输出节点电压/相角和支路潮流，那么每个节点的注入有两种算法：

1. 从电压和 Ybus 算：$S=V\odot\operatorname{conj}(Y_{\text{bus}}V)$；
2. 从支路潮流按 KCL 汇总：把该节点相连支路的注入功率加起来。

两者应当相等。这个残差在全部节点上都可算，包括 PV 节点的 Q 和平衡节点的
P/Q，不需要真值。它的作用是让“电压/相角头”和“支路潮流头”彼此一致；
如果支路潮流本身就是从同一组 V/θ 算出来的，那么这个残差恒为 0，
不会提供新信息。所以它只对**独立预测的多个头**有意义。

物理项的一个现实限制：**真实字段表没有单列变压器变比**。
所以在只用字段表字段的阶段，物理残差最好只加在线路（`branch_type=0`）上；
自建数据预训练时可以用 `aux_tap` 作为“老师”算完整 Ybus，但要清楚这只是
训练期的特权信息，不能变成模型输入。

#### 4. 辅助监督项（只建议在自建数据预训练时用）

自建数据里，PV 节点的 Q、平衡节点的 P/Q 其实是知道的，存在
`aux_net_p_mw`、`aux_net_q_mvar` 里；节点相角存在 `aux_va_deg` 里。
如果模型有对应的辅助头，可以加低权重的辅助 loss：

$$
\mathcal L_{\text{aux}}
= \lambda_Q \sum_{i\in PV}\ell(\hat Q_i,Q_i^{\text{aux}})
+ \lambda_S \sum_{i\in REF}\left[\ell(\hat P_i,P_i^{\text{aux}})+\ell(\hat Q_i,Q_i^{\text{aux}})\right]
$$

但要注意两点：

1. 这些量**不是比赛要求的输出**，比赛训练数据也不一定提供这些标签；
   迁移到比赛数据时，这一项很可能要整体去掉。
2. 它们只能用于 loss，**不能作为输入**。`aux_*` 是辅助标签，不是特征。

#### 5. 总损失与训练顺序

一个实用的组合是：

$$
\mathcal L
= \mathcal L_{\text{sup}}
+ \lambda_{\text{known}}\mathcal L_{\text{known}}
+ \lambda_{\text{phys}}\mathcal L_{\text{phys}}
+ \lambda_{\text{aux}}\mathcal L_{\text{aux}}
$$

建议分阶段加：

1. **先只训 $\mathcal L_{\text{sup}}$**，确认模型能复现官方输出；
2. 加 $\mathcal L_{\text{known}}$ 和线路上的物理残差，观察是否改善
   structural 掩码下的 Vm/Δθ 误差；
3. 自建数据预训练时再加完整物理项和辅助项；
4. 迁移到比赛数据时，按“比赛到底给了哪些标签”逐项删减，
   只保留能算的项。

最后是尺度问题：Vm 的误差是 $10^{-2}$ 量级，支路功率是 $10^2$ 量级，
Δθ 只有几度。直接相加会让功率项主导梯度。做法是先按 `stats.json`
标准化每个通道，或者把功率除以 `baseMVA=100` 换成 p.u.，再加权。
损失函数建议用 Huber/SmoothL1，比纯 MSE 更抗离群样本。

训练时建议至少记录这些指标，不要只看总 loss：

| 指标 | 为什么看 |
|---|---|
| Vm 的 MAE/RMSE（p.u.） | 官方输出之一，量级小但很重要 |
| Δθ 的 MAE（度） | 直接反映相角差预测质量 |
| Pf/Pt/Qf/Qt 的 MAE（MW/MVar） | 官方输出的主要部分 |
| 已知节点 vs 待预测节点的 Vm 误差 | 区分“抄输入”和“真预测” |

## 6.9 本章小结

这一章是“操作手册”：

# 附录 C 常见问题

**Q1：为什么节点 P/Q 是净注入，而不是负荷？**

因为潮流方程里的 $S_i$ 是“节点向电网注入的净功率”。
负荷是负注入，发电是正注入；一个节点可能两者都有，必须相减。
母线 39 就是典型例子：1000 MW 发电、1104 MW 负荷，净注入是 -104 MW。

**Q2：为什么 PQ 母线的输入 V 是 0？**

因为它的 V 是未知量，输入位置只能填占位符。掩码 `mask_V=1` 告诉模型
“这个 0 不是真实电压”。不要把占位符当成测量值。

**Q3：为什么 B/2 不能再除以 2？**

字段表给的已经是 B/2。PYPOWER 的 `b_pu` 是总 B，所以从 PYPOWER 导出时
要除以 2；从比赛数据读入时直接用。两者不要重复处理。变压器该列为空时
按 0 处理，不要填均值。

**Q4：为什么变压器支路的潮流可能预测不准？**

因为真实字段表没有单列变比。支路表虽然给了 L/T、首末端电压等级和
额定容量，但不能还原出 PYPOWER 里那个 1.006~1.070 的调压变比。
IEEE 39 有 12 条变压器支路，其中 11 条变比不等于 1。模型如果不知道变比，
这些支路的潮流就会有系统性误差。本数据集把变比放在 `aux_tap` 里，
只供物理复算和诊断；迁移时要向主办方确认是否另有变比来源。

v1 先用“全部变比 = 1”的约定训练：`tap` 不进入模型，输出仍用官方标签
监督。这样不会因为缺失字段卡住研发，但变压器支路的误差要单独看。
后续拿到真实变比，再把 `tap` 加入输入做微调。

**Q5：为什么低负荷时会出现正相角？**

因为非平衡机的发电固定，负荷降低后，功率可能从其他发电机倒送回平衡机。
相角的正负取决于功率方向，不一定是负的。样本 0 的节点相角最大值是
21.8°，就是这种情况。

**Q6：为什么输出没有节点相角？**

任务要求只输出支路的相角差。绝对相角依赖参考节点，单独输出意义不大。
字段表虽然有节点电压相角，但那是训练数据里的潮流解；本数据集把它放在
`aux_va_deg` 里，供分析和自检，不作为官方标签，也不作为输入。

**Q7：已知节点的 Vm 还要不要算损失？**

要。赛题要求输出全部 N 个节点。已知节点的输出是“送分题”，
但如果你想让指标更能反映真实能力，可以额外报告“只在掩码为 1 的节点上”
的误差。建议训练时对所有节点算损失，评估时同时报告全量和待预测子集。

**Q8：怎么做训练/验证/测试划分？**

当前只有一张网架，建议按 `sample_id` 做 80/10/10 划分，或按
`case_hash` 去重后划分。不要按分片划分（分片是顺序切的，可能引入
运行方式的系统性差异）。如果以后加入多张网架，按 `topology_hash` 分组划分，
避免同一拓扑的样本同时出现在训练和测试里。

**Q9：训练时要不要对输入/输出归一化？**

建议要。P/Q 的量级是几百 MW，V 是 1 p.u. 左右，支路潮流是几百 MW，
直接混在一起训练会让优化很难。可以用 `stats.json` 里的均值和标准差做
z-score。但提交前必须反变换回物理量。

**Q10：为什么当前数据全部收敛？**

因为 σ 区间选得比较温和（0.8～1.10），潮流方程在这段范围内都有解。
这样样本质量稳定，适合预训练。但“全部收敛”只说明**数值可解**，
不代表**调度可行**：非平衡机固定时，平衡机在大量样本中超出 `Pmax`，
详见 4.3.3。要覆盖不收敛/病态样本，需要放宽 σ 或使用连续潮流，
这是下一阶段的任务。
