# 1.9 ~ 1.11　节点类型、Ybus 手工算例与 6 个数据陷阱

> PQ/PV/平衡节点、支路参数怎么变成电路、必须知道的数据特性

## 1.9 节点类型：PQ / PV / 平衡

这是潮流计算最核心的概念。三条母线的量"已知两个、求一个"：

| 类型码 | 名称 | 已知量 | 未知量 | 本算例数量 |
|---:|---|---|---|---:|
| 1 | PQ 节点 | `P`、`Q` | `Vm`、`θ` | **29** |
| 2 | PV 节点 | `P`、`Vm` | `Q`、`θ` | **9** |
| 3 | 平衡节点（slack） | `Vm`、`θ` | `P`、`Q` | **1** |

本算例的具体分布是：

```text
平衡节点：31
PV  节点：30, 32, 33, 34, 35, 36, 37, 38, 39   （共 9 个，都接发电机）
PQ  节点：1 ~ 29                                （共 29 个）
```

**为什么必须有平衡节点？** 因为网络里存在有功损耗（本算例 43.64 MW），
发电和负荷不可能刚好相等。总要有一台机组"多退少补"，承担这个差额。
平衡节点就是干这个的：它的 P、Q 不设定，而是解完之后**算出来**的。

于是未知量总数是：

$$2 \times 39 - 9_{\text{PV 的 Vm 已知}} - 2_{\text{平衡的 Vm,θ 已知}} = 78 - 11 = 67$$

**67 个未知量**，这就是要求解的非线性方程组规模。

## 1.10 支路参数怎么变成电路（一个手工算例）

拿第 1 条支路（母线 1 → 2）举例，它的参数是 r = 0.0035、x = 0.0411、b = 0.6987。

**第一步：算串联导纳。** 串联阻抗 `z = r + jx`，导纳是它的倒数：

```python
z = 0.0035 + 0.0411j
y = 1 / z          # = 2.0571 - 24.1557j
```

**第二步：算充电电纳。** π 型等值电路把总电纳 `b` 平均分到两端：

```python
y_charging_half = 1j * 0.6987 / 2    # = 0.3493j
```

**第三步：填入 Ybus 矩阵。** 这条支路对 `Ybus` 的贡献是：

$$
\begin{aligned}
Y_{11} &\mathrel{+}= y + \frac{jb}{2} \\
Y_{22} &\mathrel{+}= y + \frac{jb}{2} \\
Y_{12} &= Y_{21} = -y
\end{aligned}
$$

把两条挂在母线 1 上的支路（1-2 和 1-39）都加完，就得到 `Ybus[0,0]`：

```text
Ybus[0][0] = 3.6545 - 63.3675j
```

你可以用这一段代码亲手验证：

```python
import numpy as np
from pypower.api import case39, ext2int, makeYbus

ppc = ext2int(case39())
Ybus, Yf, Yt = makeYbus(ppc["baseMVA"], ppc["bus"], ppc["branch"])
print(Ybus.toarray()[:3, :3].round(4))
```

输出：

```text
[[ 3.6545 -63.3675j  -2.0571 +24.1557j   0.      +0.j    ]
 [ -2.0571 +24.1557j 64.6457-211.8706j  -5.6596 +65.7379j]
 [  0.      +0.j     -5.6596 +65.7379j  14.6906-186.843j ]]
```

`Ybus` 的关键特征：

| 指标 | 数值 |
|---|---:|
| 规模 | 39 × 39 |
| 非零元 | 131 个 |
| 稀疏度 | 131 / 1521 = 8.6%（**非常稀疏**） |

**稀疏是潮流计算能算得快、算得大的根本原因。** 39 节点的 Ybus 只有 8.6% 非零；
真实的几千节点电网，稀疏度会更低。工程求解器都用稀疏矩阵技术，而不是稠密矩阵。

## 1.11 数据里必须知道的 6 个细节

这一节非常重要，能帮你避开很多"以为是 bug、其实是数据特性"的困惑。

### ① 算例自带的初值，已经几乎是答案

`case39` 的 `bus` 表里，`VM`、`VA` 两列**不是随便填的**，而是一个**已经求解过的**
潮流的解。实测差异：

```text
算例初值 vs 求解结果：max |ΔVm| = 4.80e-08 pu
                     max |ΔVa| = 4.95e-07 度
初值处的最大功率失配 = 2.91e-05 pu
```

因为初值处的失配（2.91e-05）已经小于通常的收敛容差（1e-8 ~ 1e-10 量级附近就够用了，
而这个算例的容差设成 1e-10 时第一次校正后立刻达标），所以 PYPOWER 打印的是
**"converged in 1 iterations"**。

**这不是 bug，也不是牛顿法只能迭代 1 次。** 想看真正的迭代过程，请做 2.10 节的
平启动实验。

### ② 母线 9 和 24 的 `Qd` 是负数

```text
母线 9 : Qd = -66.6 Mvar
母线 24: Qd = -92.2 Mvar
```

负的负荷 = 在向系统**注入无功**，代表这两个点装了无功补偿装置（电容器）。
不要把它们误改成 0，否则潮流结果会变。

### ③ 平衡母线 31 自己也有负荷

```text
母线 31: PD = 9.2 MW, QD = 4.6 Mvar
```

平衡节点**不等于**"没有负荷的节点"。母线 31 既挂平衡机，又挂一个小负荷。
所以总负荷 6254.23 MW 里包含了这 9.2 MW。

### ④ 母线 39 是 PV 节点，却挂了最大的负荷

```text
母线 39: type = 2 (PV), PD = 1104 MW, QD = 250 Mvar
```

一个节点**同时**可以是发电机节点和重负荷节点。它的净注入是
`Pg - Pd = 1000 - 1104 = -104 MW`，即整体上是**受电**的。

### ⑤ 发电机 37 的无功越下限

求解后 `Qg = -1.37 Mvar`，而数据规定 `Qmin = 0 Mvar`。

**PYPOWER 的潮流计算不会自动处理这个越限。** 潮流计算只是解方程，不负责
"发现越限就把 PV 节点转成 PQ 节点"——那是需要外层循环的**无功限值处理**
（PYPOWER 里要靠 `runpf` 反复调用或自己写逻辑）。看到越限不要慌，先确认
是不是数据本身如此。

### ⑥ 发电机 31 的有功超过 `Pmax`

```text
Pg = 677.87 MW  >  Pmax = 646 MW
```

原因和 ⑤ 一样：母线 31 是**平衡机**，它的 `PG` 是解出来的兜底值，
不是调度设定。数据里的 `PG = 677.871` 只是初值。原始数据从上游继承了这个
特性，**保留原始数据时不要悄悄"修正"它**。
